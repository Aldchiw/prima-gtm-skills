// Pipeline-only, stage-0 contacts only: a single button that expands into
// an inline Email/LinkedIn channel picker (see showChannelPicker/startSequence).
function startSequenceHtml(active){
  return `<span class="startwrap" data-contact-id="${escAttr(active.id)}"><button type="button" class="start-seq">Start sequence</button></span>`;
}

// `followupWorst` truthy = a followup/FUP-on-time card (keeps the old
// numeric stage select). Falsy = a pipeline card: no select at all: a
// "Start sequence" button on not-yet-contacted (stage 0) contacts, nothing
// on contacts already in flow (their progress lives in cadence()/the
// followup sections instead).
function contactBlock(l, active, followupWorst){
  const contacts = l.contacts;
  if(!contacts.length){
    return `<div class="contact contact-empty">No contact identified yet</div>`;
  }
  const selector = contacts.length>1
    ? `<select class="contactsel" data-co="${escAttr(l.co)}" aria-label="Choose contact at ${escAttr(l.co)}">
         ${contacts.map((c,i)=>`<option value="${i}" ${c===active?"selected":""}>${c.name} — ${stageLabel(c.stage)}</option>`).join("")}
       </select>`
    : "";
  const links = [];
  if(active.email) links.push(`<a href="mailto:${active.email}">${active.email}</a>`);
  if(active.linkedin) links.push(`<a href="${active.linkedin}" target="_blank">LinkedIn</a>`);
  const teamStatus = active.team_status ? `<span class="team-status">${active.team_status}</span>` : "";
  const notes = active.notes ? `<div class="team-notes">${active.notes}</div>` : "";
  // Pipeline cards no longer get a stage control here -- "Start sequence"
  // lives in the card footer instead (see cardHtml).
  const stageControl = (followupWorst && active.id) ? stageSelectHtml(active) : "";
  return `<div class="contact">
    <div class="contact-row"><b>${active.name}</b> · ${active.title||"—"}${teamStatus}${stageControl}${selector}</div>
    ${links.length?`<div class="contact-links">${links.join("")}</div>`:""}
    ${notes}
  </div>`;
}

NOTA: el <a> de LinkedIn solo se agrega si active.linkedin es truthy (línea 911) -- si viene falsy
(null/""), simplemente no se pinta ningún link, no hay <a href=""> roto para LinkedIn como sí puede
pasar con signal.url en la sección 1.

4. Handler de click delegado sobre las cards (contexto, por si el bug fuera de intercepción de click)
============================================================
Archivo: docs/index.html, líneas 1178-1193

// Clicking anywhere on an in-flow card's "dead" area (not a button/select/
// link/input/textarea/label -- Done, Stopped, Start sequence, the stage
// select, LinkedIn/source links) opens the touch modal for that card's
// worst-in-flow contact. Cold-pipeline and fully-closed cards never get the
// "clickable" class/data-* (see cardHtml), so they're inert here regardless
// of what's clicked. Delegated on #list's parent container (never itself re-rendered) so it
// keeps working across every renderFollowups()/renderSections() re-render
// of #followups/#list underneath it.
el("#list").parentElement.addEventListener("click", e => {
  const card = e.target.closest(".card.clickable");
  if (!card) return;
  if (e.target.closest("button, select, a, input, textarea, label")) return;
  const contact = findContactById(card.dataset.contactId);
  if (!contact) return;
  openTouchModal(contact, card.dataset.account);
});

NOTA: este handler explícitamente EXCLUYE clicks dentro de un <a> (`e.target.closest("button, select,
a, input, textarea, label")` -> return). Búsqueda completa en el archivo confirma que no hay ningún
otro addEventListener("click", ...) que pueda interceptar el <a>, y no hay ningún preventDefault(),
window.open(), location.href= ni location.assign() en todo docs/index.html. Es decir: NO hay
intercepción JS del click sobre los <a> -- el navegador debería manejar la navegación de forma nativa
según el href que reciba.
